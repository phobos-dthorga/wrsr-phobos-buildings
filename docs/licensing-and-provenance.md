# Licensing and provenance

## First-party work

Use the same MIT licence as Observatory for original project code, documentation and
project-owned original assets unless a file has an explicit different notice. Preserve
copyright and licence text in derivative distributions. Requests for a project link
and visible credit are courtesy requests, not added licence restrictions.

See [LICENSE](../LICENSE), [NOTICE](../NOTICE), and the
[MIT licence reference](https://choosealicense.com/licenses/mit/).

## External inputs

A model being editable or locally subscribed does not grant redistribution permission.
No Workshop donor geometry, texture, screenshot, extracted part or proprietary game
file is imported into this public foundation. Never copy the private collection or its
history here. The earlier donor investigations can inform research without providing
source assets for the public mod.

Every future external asset needs an explicit source URL, creator, licence/permission
evidence, permitted modification/distribution, required notices and a content hash.
If the terms are unknown, it cannot enter a release. The project's MIT licence does
not relicense someone else's work.

Original textures or appropriately licensed CC0 assets are possible routes. Check the
specific asset terms, not just a search-result image. [ambientCG](https://docs.ambientcg.com/license/)
and [Poly Haven](https://polyhaven.com/license) publish their CC0 terms. These are
candidate sources; this repository has not downloaded or adopted their assets.

Keep tool licences separate from generated-asset provenance. Blender, 3Division
exporters and other third-party tools are not vendored or relicensed by this repository.
No proprietary tool binary or unreviewed exporter source is part of a release package.

## Planned records

The shared catalogue lists planned components and their intended first-party MIT
status. It does not assert ownership of an asset that has not yet been created.
Before an asset is marked ready, add creator/date, source files, licence and verification
evidence. A future release inventory must cover geometry, textures, icons, sounds and
every external dependency.
